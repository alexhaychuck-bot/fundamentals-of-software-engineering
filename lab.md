# Лабораторна робота №3

## Тема
Software Development Life Cycle (SDLC) — життєвий цикл програмного забезпечення.

## Варіант 5 — Список покупок

## 1. Планування

Мета проєкту — створити простий застосунок «Список покупок».

Користувач повинен мати можливість створювати список товарів для магазину, додавати нові товари, редагувати їх, видаляти та позначати вже придбані товари.

## 2. Аналіз вимог (User Stories)

1. Як користувач, я хочу додавати товар до списку покупок, щоб не забути його купити. **Must have**

2. Як користувач, я хочу видаляти товар зі списку, якщо він мені більше не потрібен. **Must have**

3. Як користувач, я хочу редагувати назву та кількість товару, щоб виправляти інформацію.

4. Як користувач, я хочу позначати товар як придбаний, щоб бачити, що вже куплено.

5. Як користувач, я хочу бачити всі товари в одному списку, щоб зручно користуватися ним у магазині.

## 3. Дизайн (Прототип)

Прототип складається з двох екранів:

1. Головний екран зі списком покупок.
2. Екран додавання нового товару.

## 4. Реалізація (Псевдокод)

Ключова функція — додавання нового товару.

```text
function addProduct(name, quantity):

    if name is empty:
        return "Помилка: введіть назву товару"

    if quantity <= 0:
        return "Помилка: кількість повинна бути більше 0"

    product = createProduct(name, quantity)

    shoppingList.add(product)

    return "Товар успішно додано"
```

## 5. Тестування

1. Додати товар «Молоко», кількість 2 → товар з'являється у списку.

2. Додати товар без назви → система показує помилку, товар не додається.

3. Вказати кількість 0 → система показує помилку.

4. Видалити товар «Хліб» → товар зникає зі списку.

5. Позначити товар «Молоко» як придбаний → товар відображається як виконаний.

## 6. Висновок

Для цього проєкту доцільно використовувати Agile.

Цей підхід дозволяє спочатку створити просту базову версію застосунку, а потім поступово додавати нові функції, наприклад категорії товарів, декілька списків або спільний доступ.

Waterfall для такого невеликого проєкту був би менш гнучким, а Spiral — занадто складним.
